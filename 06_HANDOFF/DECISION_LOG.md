## DEC-001 — Repo is Source of Truth (Not Chat)

**Date:** 2026-05-26
**Made By:** Human (User) via project brief
**Phase:** 0
**Status:** Active

### Decision
All agent communication, decisions, and outputs go through repo files. No agent-to-agent communication via chat or real-time messaging.

### Rationale
Prevents invisible state changes, enables auditability, allows any agent to pick up where another left off without losing context.

### Impact
All agents must write outputs to files. All decisions must be logged here.

## DEC-002 — All BRAIN Files Use [FILL] Placeholders in Phase 0

**Date:** 2026-05-26
**Made By:** Claude Code (Builder Agent)
**Phase:** 0
**Status:** Active

### Decision
BRAIN files are created with structure and `[FILL]` placeholders instead of invented brand data.

### Rationale
Builder Agent does not have real Vị Cuốn brand data. Inventing data would create incorrect foundations. User fills real data before Phase 1.

### Impact
Phase 1 cannot start until user fills all BRAIN file placeholders.

---

## DEC-003 — Comment Reply Auto-Post Disabled for Complaints

**Date:** 2026-05-26
**Made By:** Claude Code (Builder Agent)
**Phase:** 0
**Status:** Active

### Decision
The `auto_post_safe` flag is always `false` for comment category `complaint` regardless of confidence score.

### Rationale
Automated complaint responses carry brand reputation risk. Human review required for all negative sentiment interactions.

### Impact
Comment Reply Agent will never auto-post replies to complaints. All complaints route to human via Telegram.

---

## DEC-004 — Budget Values Are Always Placeholders

**Date:** 2026-05-26
**Made By:** Claude Code (Builder Agent)
**Phase:** 0
**Status:** Active

### Decision
Ads Pack schema requires `budget_note` to contain a `[PLACEHOLDER]` notice. No real monetary values are generated by AI.

### Rationale
Prevents accidental ad spend. Budget decisions require human judgment.

### Impact
Humans must manually set budgets before uploading to Ads Manager.

---

## DEC-005 — Session Cap at 10 Messages

**Date:** 2026-05-26
**Made By:** Human (User) via project brief
**Phase:** 0
**Status:** Active

### Decision
Every agent session is capped at 10 back-and-forth messages. At limit, agent creates SESSION_SUMMARY.md update and stops.

### Rationale
Keeps sessions focused, prevents context drift, ensures handoff documentation is always current.

### Impact
Complex tasks may span multiple sessions. SESSION_HANDOFF.md bridges sessions.
