## What Are Output Templates?

Output templates are pre-structured markdown files that agents use to produce consistent, schema-compliant outputs. Each template:

- Mirrors every field from its corresponding Phase 3 JSON schema.
- Uses placeholder values (`[TO_FILL]`, `[OWNER_TO_PROVIDE_OFFER]`, `[AUTO_GENERATED]`) so agents know exactly what to fill.
- Sets safe defaults (`approval_status: Draft`, `human_review_required: true`) that cannot be skipped.
- Is reusable across any F&B brand — not locked to Vị Cuốn.

## How Templates Map to Schemas

Each template field maps 1:1 to a schema property. The mapping rules are:

| Schema field type | Template placeholder |
|-------------------|---------------------|
| Required field, agent fills | `[TO_FILL]` |
| Required field, Owner must provide | `[OWNER_TO_PROVIDE_OFFER]` |
| Auto-generated by system or agent | `[AUTO_GENERATED]` |
| Optional field (nullable in schema) | `[TO_FILL or null]` |
| Constant field (`const: true`) | Written as literal value — e.g., `true` |
| Default value in schema | Written as literal default — e.g., `Draft` |

If a schema field has `const: true`, the template writes the value as a literal and agents must not change it.

## How Templates Support Future n8n / LangGraph Workflows

In Phase 5 and beyond, n8n and LangGraph will consume agent outputs. Templates ensure those outputs are predictable:

- n8n nodes can parse template outputs by field heading (`## field_name`) or by converting to JSON using schema.
- LangGraph agents can read template outputs as structured context for chaining decisions.
- Every template includes `approval_status` — n8n workflows can gate on this field before triggering publishing actions.
- Every template includes `created_by_agent` — LangGraph can route outputs to the correct downstream agent.

No template hardcodes pipeline-specific logic. Templates are content contracts, not workflow scripts.

## How Brand Brain Can Be Replaced for Another F&B Brand

Templates are brand-agnostic by design. To use FnB OS V1 for a brand other than Vị Cuốn:

1. Create a new Brand Brain file: `brand-brain/[brand-slug].md` — mirror the structure of `brand-brain/vi-cuon.md`.
2. Update `brand_id` and `brand_name` in each template output to the new brand.
3. Update `target_audience` descriptions to match the new brand's segments.
4. Update `offer` fields with the new brand's confirmed offers.
5. Keep all schema field names, enum values, and template structure unchanged — these are system-level contracts, not brand-specific.

The core agent behavior, SOPs, templates, and schemas do not need to change when switching brands. Only the Brand Brain and the filled template values change.

## Required: approval_status

Every template output must include `approval_status`. Rules:

- Default on creation: `Draft`
- Only Owner may set: `Approved`
- `Published` and `Scheduled` require prior `Approved` + `approved_at` timestamp
- Agents must not self-approve or skip the approval gate

---

## Required: Logging

Every agent output must be accompanied by a log entry using `templates/log-entry-template.md`. Log entries must be written to:

- `logs/AGENT_ACTIVITY_LOG.md` — one row per agent action
- `09_LOGS/PHASE_LOG.md` — one entry per phase milestone

Logs are the operational record of the system. They are required for:
- Audit and review by Owner and Codex
- Debugging and revision tracking
- Future n8n/LangGraph traceability
