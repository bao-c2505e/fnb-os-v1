## How to Use This Template

1. Copy this entire file.
2. Rename it: `logs/test_data_register_[WORKFLOW_NAME]_[PHASE]_[DATE].md`
   - Example: `logs/test_data_register_content_auto_phase26_2026-07-01.md`
3. Fill one entry per test data set.
4. Get Owner sign-off before using any data set in sandbox execution.
5. Remove or archive data after testing. Do not leave real customer data in the repo.

---

> **Rule:** If the field "Real customer data used?" is YES, stop. Real customer data requires separate explicit Owner approval for each use and must comply with applicable data privacy requirements. Default answer must be NO.

## Data Classification Rules

| Classification | Definition | Allowed in Sandbox? |
|---------------|------------|---------------------|
| **Synthetic** | Fully invented. No real person, order, or message involved. | YES — preferred |
| **Mock** | Based on real data structure but all values replaced with fake equivalents. | YES — confirm no real values remain |
| **Real** | Actual customer name, phone, email, message, or order data. | NO — requires separate explicit Owner approval, not default |

---

## Forbidden Data Practices

| Forbidden | Why |
|-----------|-----|
| Real customer names, phone numbers, email addresses | Personal data — privacy risk; requires explicit approval |
| Real Zalo/Facebook message content | Customer-facing data — privacy and consent risk |
| Real order IDs linked to real customers | Customer data — privacy risk |
| API credentials or tokens as "test values" | Security risk — never use real credentials even in sandbox |
| Data copied directly from production n8n logs | May contain real customer PII |
| Sharing test data outside the repo without Owner approval | Data governance risk |
